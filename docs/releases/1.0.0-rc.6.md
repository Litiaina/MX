# MX 1.0.0-rc.6 — 2026-10-20

[Documentation](../README.md) · [Validation](../../TESTING.md) · [Changelog](../../CHANGELOG.md)

**Release candidate, not stable 1.0.0.** RC.6 packages the locally tested
Collaboration and record-attachment fixes. Published RC.5 and its assets remain
unchanged. No production deployment is restarted merely by publishing a release.

## Fixes

- Paste browser-exposed files of any permitted attachment type into Collaboration,
  not only images. Preserve document names and ordinary text paste; deduplicate
  pending files and retain conversation-specific drafts.
- Drop files onto a conversation without navigating away. Files queue for review
  and are sent only after choosing Send. Folder/limit problems are explained
  beside the composer; share whole folders through Drive instead.
- Open supported Word/Excel and other Office chat attachments in the bundled
  browser engine, without a server LibreOffice/PDF conversion dependency.
- Use the same viewer for stored module/record Office attachments. Keep the
  original record open, preserve its values/history and provide Return to record.
- Add direct Open in MX Office actions to shared Drive cards, retaining existing
  Drive access, editing permissions, file identity and version handling.
- Close old previews on conversation changes and ignore obsolete file-list
  responses. Keep Open/Download recovery for blocked popups and unsupported
  graphics/formats. A separate attachment entry avoids old cached Drive shells.

Chat/record attachments are **read-only copies**, not writable Drive versions.
Opening them does not autosave, create a Drive item or retain a private offline
draft. Download original preserves the original bytes. Use the actual shared
Drive item for editing and MX-owned versioned saves. Queued record files must
first be uploaded with the record before opening them in Office.

## Upgrade and rollback

From RC.5 or an older official 1.x candidate, use **Administration → Updates →
Check for updates → Download and verify → Install now…**, or the saved automatic
maintenance policy. Save open work before installation, then refresh the main
MX tab and reopen Office viewers. Offline updates use the same signed package.

The Ed25519 publisher key remains `fdf69f67562fb715`; the independent update
worker, final SQLite backup and failed-activation rollback protocol are unchanged.
No new database schema or N1 storage-format migration is introduced. Existing
modules, records, accounts, permissions and file objects remain intact. Keep the
verified pre-update backup; restore the paired previous application and snapshot
through the established rollback procedure, not an older binary alone.

New installs use `mx-1.0.0-rc.6-x86_64-unknown-linux-gnu.tar.gz`. Managed/offline
updates use `mx-x86_64-unknown-linux-gnu.mxupdate` and its signed `.json` metadata.
N1 remains independently versioned at `1.0.0-RC.1`, NOA v1, storage encoding 4.

## Qualification boundaries

Word/Excel attachment rendering is tested with the actual bundled engine in
Chromium, Brave and Firefox. Linux WebKit on the qualification host lacks worker
WebGL: its explicit error and unchanged original-download recovery are tested,
not successful Office rendering. No Internet Office service is required.

Clipboard/drop automation uses browser DataTransfer events, not a physical
Windows clipboard. Desktop/file-manager behavior still needs target-client
acceptance. If the browser exposes no clipboard file bytes, use Attach or
drag/drop; MX never fetches a pasted local path or URL as a file.

Existing privacy/calculation and desktop-notification limits from
[RC.5](1.0.0-rc.5.md#acceptance-boundaries) still apply. These checks are not
stable-release certification, physical power-loss testing or verification of
every Office format. Detailed evidence and repeatable commands are in
[TESTING.md](../../TESTING.md).
