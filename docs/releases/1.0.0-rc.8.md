# MX 1.0.0-rc.8 — 2026-10-25

[Documentation](../README.md) · [Validation](../../TESTING.md) · [Changelog](../../CHANGELOG.md)

**Release candidate, not stable 1.0.0.** This release fixes duplicated clipboard
attachments and improves navigation for large numbers of modules. It also fixes
Office offline-preparation assets discovered during release verification.
Published RC.7 and earlier assets remain unchanged.

## Changes users will see

- Pasting a file or screenshot into Collaboration queues one attachment per
  original, even when the browser supplies different timestamps in its clipboard
  representations. Ordinary text paste, file names, drag/drop and distinct file
  selections retain their behavior.
- The collapsed sidebar has one **Modules** entry. Open it to search modules by
  name, description or group; browse 40 results per page. Expanded navigation has
  a searchable shortcut section showing at most 12 matches, plus **Browse all**.
  Only modules allowed by the account's existing permissions appear.
- Configure **Navigation group** and **Navigation order** in **Administration →
  Modules & fields → Configure [module] → Module details**. Lower order numbers
  appear first; 10, 20, 30 leave room for insertions. Existing saved order is used.
- Office's public offline manifest no longer requests two deleted entry scripts.
  Both public editor shells and their actual dependencies are included, and the
  production build checks final files and the worker generation. No documents,
  tokens or API responses are added to this public-asset cache.

Fresh installations remain blank; no modules, business fields or records are
seeded. This release does not introduce ERP/DMS workflow features.

## Install and verify

1. Save active work. Use **Administration → Updates → Check for updates →
   Download and verify → Install now…**, or your saved maintenance policy.
2. Refresh the main MX tab. Existing open tabs keep their loaded JavaScript
   until refreshed.
3. Open **Modules**, search for an existing workspace and check that its records
   and your access remain correct. Expanded navigation also offers shortcuts.
4. Paste one screenshot in Collaboration and confirm there is one attachment
   before sending. Ordinary Ctrl+C/Ctrl+V text should remain unchanged.
5. If you use prepared offline Office copies, reopen Office while connected and
   let preparation complete. Browser-trusted HTTPS, sufficient device storage and
   supported graphics are still required; a certificate-warning bypass is not
   sufficient. Keep a separate copy of important unsynchronized edits.

New installation: `mx-1.0.0-rc.8-x86_64-unknown-linux-gnu.tar.gz`.
Managed/offline update: `mx-x86_64-unknown-linux-gnu.mxupdate` plus signed
`mx-x86_64-unknown-linux-gnu.json`. Checksums, publisher public key and build
provenance accompany the release. No Cargo, Node or separate Office server is
needed at runtime.

## Compatibility and safety

The publisher key remains **fdf69f67562fb715**. Signed package format, independent
worker, final SQLite backup, maintenance policy and failed-activation rollback
are unchanged. No new database schema, record/field renumbering or N1 format
migration is introduced. Existing files, histories, account grants, personal
settings and RC.7 upload policies are retained.

N1 remains independently versioned at **1.0.0-RC.1**, NOA v1, storage encoding 4.
Rollback restores the paired prior application and its verified pre-update
SQLite snapshot, not an older binary alone. Publication does not deploy to or
restart an existing production or populated test installation.

## Validation boundaries

**192 native tests passed** (two opt-in ignored), **364 frontend tests / 59
files passed**, with zero Svelte errors/warnings. All nine final-build suites
pass, including 100-module navigation, clipboard/file handling, attachment
privacy/viewing, Drive controls, upload policies and an 11-check isolated
**RC.7 → RC.8** systemd activation/backup/rollback/recovery rehearsal. Real
service-worker cache installation and both public offline shells pass in
Chromium and Firefox.

See the RC.8 section in [TESTING.md](../../TESTING.md) for completed checks and
release-build upgrade rehearsals. Physical Windows clipboard behavior, every
complex Office document, operating-system notification banners and physical
power-cut durability are not certified by automated browser tests. Linux WebKit
on the qualification host lacks worker WebGL; its qualified outcome is an
explicit fallback and byte-exact original download, not successful Office
rendering. The Vite large-chunk advisory remains.
