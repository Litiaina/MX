## Changes

This candidate fits the collapsed navigation rail to the selected
interface scale. The existing logo, search, module icons and footer remain
centered instead of clipping an expanded-width layout. Expanded/mobile search
and navigation rows fit their drawer; invisible search controls are excluded
from keyboard focus. Branding assets and configured organization identity are
unchanged.

Record browsing defaults to Pages; saved choices remain respected. Continuous
scroll is optional, with stable measured column widths when switching from
Pages, a consistently reachable horizontal scrollbar, bounded row rendering,
and schema reuse/cancellation during view changes.

New databases start with no starter module, business fields or records.
Administration provides a first-module creation path. Existing modules,
including an earlier empty generic Records module, are preserved on upgrades;
legacy records/fields retain their compatibility workspace.

There is no new database schema migration, N1 storage migration, credential
reset, Office service or runtime application dependency. Existing records,
permissions, Drive objects, file versions and deployment configuration remain
in place. The matching executable includes the fresh-installation behavior;
sidebar and record-view corrections are frontend changes.

## Update an existing managed RC.1 deployment

1. Sign in as Administrator and open **Administration → Updates**.
2. Choose **Check for updates**. The deployment must permit the **rc** channel
   and trust the existing publisher key `fdf69f67562fb715`.
3. Confirm `1.0.0-rc.2`, then **Download and verify**.
4. Save open forms and Office documents; calls/transfers are interrupted by
   the restart. Choose **Install now…** when ready.
5. The independent worker takes and verifies the final SQLite rollback snapshot,
   activates matching native/frontend files and verifies health before reopening
   writes. A failed activation retains the existing paired rollback behavior.
6. After reconnection, confirm RC.2 in Updates. Check collapsed/expanded
   navigation at your normal UI scale, then verify records and a file download.

The same publisher key signs this candidate; operators must not generate a new
trust key or install the publisher private key. Deployment installation policy
stays unchanged. Preparing/publishing RC.2 does not install it on MCH or any
other running deployment.

For a disconnected deployment, upload the published signed `.mxupdate` package
through **Offline update package → Upload and verify**, then install it through
the same worker. New installations use the matching initial-install archive
and the [deployment guide](../deployment.md).

## Compatibility and qualification

The published target remains Linux x86-64 GNU, glibc 2.39+, OpenSSL 3, zlib,
Zstandard and the standard GCC runtime, as documented for
[RC.1](1.0.0-rc.1.md#release-assets-and-initial-installation).

Validation evidence is recorded in [TESTING.md](../../TESTING.md). A focused UI
regression pass does not remove the existing Office, real-device media,
accessibility, security or physical power-loss qualification limits documented
in [RC.1](1.0.0-rc.1.md#not-included-or-not-guaranteed).
