# MX 1.0.0-rc.9 — 2026-10-26

[Documentation](../README.md) · [Validation](../../TESTING.md) · [Changelog](../../CHANGELOG.md)

**Release candidate, not stable 1.0.0.** RC.9 introduces configurable module
workspaces, processes and operational books. Published RC.8 and earlier assets
remain unchanged. Publication does not deploy or restart an existing server.

## What changes

- **Views & layout:** configure a module’s opening screen and ordered view tabs.
  Choose process pipelines, card directories, operations overviews, document
  libraries, full-page accounting/inventory or the existing Records interface.
  Configure card fields, summary tiles and named record-detail sections.
- **Process & actions:** define stages, permitted transitions, required fields
  and files, notes, creator/separate-reviewer policies and reapproval after edits.
  Decisions retain their exact saved record snapshot and paginated history.
- **Accounting & stock:** enable balanced exact-money journals, account balances,
  reversing entries, period cutoffs, stock receipts/issues, reservations and
  explicit release/consumption. Immutable evidence and payload-bound receipts
  protect against duplicate uncertain retries and concurrent overselling.
- **Usability and compatibility:** configuration links select the intended
  module; field archive failures name their view/process dependencies; linked
  cards show authorized names instead of UUIDs. Legacy record links open once,
  stale live events cannot leave a new module stuck loading, and record refreshes
  stop when leaving the page instead of racing browser teardown.

Fresh installations remain completely blank. Existing modules retain Records
until an administrator explicitly saves a layout. Layout changes do not convert
records, rewrite permissions, approve requests, post journals or move stock.
CRM/ERP starting points are editable configurations, not a complete prebuilt
industry application or tax/payroll/regulatory certification.

## Install and verify

1. Save active forms, Office documents and transfers. Retain a verified backup
   of SQLite and an independent N1 recovery copy. SQLite contains file references,
   not the original N1 bytes.
2. Use **Administration → Updates → Check for updates → Download and verify →
   Install now…**, or your configured maintenance policy. Deploy the matching
   executable and frontend together; do not reset the database.
3. The application creates additive tables/indexes before accepting requests.
   Existing module IDs, fields, records, ownership, history, preferences, upload
   policies and file references are retained. Reopen an existing module and
   verify its records, relationships and attachments before configuring features.
4. Under **Administration → Modules & fields**, select the intended module.
   Configure **Process & actions** for pipelines or approvals, and **Accounting
   & stock** for books. Then configure **Views & layout** and its opening view.
   Follow the [workspace](../module-workspaces.md), [process](../module-processes.md)
   and [book](../operational-books.md) guides; start with a disposable module.
5. Refresh older MX tabs to load the matching interface. Grant book access only
   to operators who may see the entire book: creator-only record access is not
   whole-book isolation. Ordinary numeric overview totals are not journal balances.

New installation: `mx-1.0.0-rc.9-x86_64-unknown-linux-gnu.tar.gz`.
Managed/offline update: `mx-x86_64-unknown-linux-gnu.mxupdate` and signed
`mx-x86_64-unknown-linux-gnu.json`. Release assets also include checksums,
publisher public key and build provenance. Cargo, Node and an external Office
server are not runtime dependencies.

## Compatibility and rollback

Publisher key **fdf69f67562fb715**, package format 1, the independent worker,
maintenance policy and final SQLite backup/failed-activation rollback protocol
are unchanged. N1 remains independently versioned at **1.0.0-RC.1**, NOA v1,
storage encoding 4; this release does not upgrade or rewrite N1.

This release adds application tables. A failed activation restores the paired
previous application and verified pre-update SQLite snapshot. Do not downgrade
only the binary after accepting new work. A later restore of a pre-update backup
would discard subsequent work and requires an explicit recovery decision.

Posted book evidence cannot be edited or deleted; corrections use compensating
entries. Once book configuration starts retained audit history, archive the
module rather than permanently deleting it. Closed periods cannot be reopened.

## Validation boundaries

225 native tests (2 existing opt-in tests ignored), 385 frontend tests and
19 browser/integration suites are recorded in [TESTING.md](../../TESTING.md).
These include four-browser workspaces and notification routing, workflow/book
regression, 100,000-record read/concurrency checks, RC.8 database preservation,
packaged assets and isolated signed activation/backup/rollback/recovery using
the final versioned executable and matching frontend.

These checks do not certify every business policy, physical power-cut durability,
every Office document, Windows clipboard behavior or OS notification banners.
Office still runs on the client. Linux WebKit without worker WebGL uses an
explicit fallback and original download, not a claimed working renderer. The
frontend large-chunk advisory remains. Validate organization-specific workflows
and accounting controls before relying on them.
