# MX 1.0.0-rc.11 — 2026-10-28

[Documentation](../README.md) · [Validation](../../TESTING.md) · [Changelog](../../CHANGELOG.md)

**Release candidate, not stable 1.0.0.** This release refines workspace appearance
and hardens mixed concurrent work. Earlier releases remain unchanged. Publication
does not itself deploy or restart an existing server.

## What changes

- **Workspace:** compact module headings, readable console-style tables, neutral
  dark surfaces and the MX product light palette. Personal column color, badges
  and bold settings are account-scoped and revision-checked. Configured branding,
  restricted fields, enlarged text and complete long text remain supported.
- **Interaction:** reduced-motion-aware transitions, safe outside/Escape dialog
  dismissal, unsaved-draft protection and retained focus after cancellation or
  a failed save. Deployment refreshes preserve personal appearance.
- **Office:** loading screens, controls and attachment viewers share MX appearance;
  browser tabs use the configured organization logo. Loading progress remains
  honest. The browser document engine is not replaced or made instantaneous.
- **Concurrent work:** records, Drive, Collaboration, administration and preferences
  share fair writer admission while readers remain separate. N1 network work stays
  outside database turns. Bounded audit batches await persistence confirmation;
  import slices commit atomically with inspectable invalid rows.
- **Notifications:** bounded durable outbox delivery interleaves with foreground
  writes. Indexed inbox/unread queries avoid full-history sorts. Read-all uses a
  durable account watermark; original payloads/read times, current access checks,
  catch-up ordering and crash recovery remain intact.
- **Durability:** FULL-synchronous WAL commits and a dedicated passive checkpoint
  worker separate acknowledgement durability from checkpoint scheduling. This
  does not certify a physical power cut or a faulty storage controller.

## Upgrade an existing deployment

1. Save forms/documents and pause new imports/transfers. Retain deployment
   configuration and independent N1 recovery copies. SQLite backups contain
   metadata and references, not the original N1 file bytes.
2. Open **Administration → Updates**. Download/verify **1.0.0-rc.11**, then use
   **Install now…**, or the configured maintenance policy. Use the signed matching
   executable/frontend pair. Do not reset, re-import or recreate the database.
3. Keep the updater's final verified pre-update SQLite snapshot and previous
   application slot. Startup adds read-all watermark metadata before requests;
   existing business values, modules, grants, file references and histories remain.
4. Refresh existing tabs. Confirm installed version `1.0.0-rc.11`; open a real
   module, make one legitimate save/edit, inspect history and download an existing
   attachment. Check a second account's notifications and configured logo/theme.
5. If a request times out, preserve the draft and reconcile the original operation
   before retrying. Record the exact action/error for support; do not delete data
   to guess around a conflict.

New installation: `mx-1.0.0-rc.11-x86_64-unknown-linux-gnu.tar.gz`.
Managed/offline update: `mx-x86_64-unknown-linux-gnu.mxupdate` plus signed
`mx-x86_64-unknown-linux-gnu.json`. Assets include checksums, publisher public key
and build/qualification provenance. No separate Office service is required.

The attached x86-64 GNU/Linux build requires glibc **2.39 or newer**, OpenSSL 3,
zlib and Zstandard runtime libraries. Other architectures/libc targets are not
included. The updater checks executable compatibility before activation; do not
force an incompatible binary into a deployment slot.

## Compatibility and rollback

Publisher key **fdf69f67562fb715**, package format 1 and the independent worker
protocol are unchanged. N1 compatibility is **1.0.0-RC.1**, NOA v1, encoding 4;
the selected test engine is commit `f1e78c58963b28efb6ae382fe95b1b4d61cc8008`.
MX's package does not upgrade N1 or change its configured limiter/storage policy.

Failed activation restores the previous binary/frontend and final verified
SQLite snapshot together. Do not downgrade only the executable against upgraded
SQLite, and do not restore a pre-update snapshot after accepting new work without
an explicit recovery decision.

## Qualification and limits

The final versioned build passed **252 native tests** (two opt-in ignored), **408
frontend tests**, zero frontend diagnostics and final package/upgrade/browser
checks; the reviewed source also passed 15 focused suites. The final extended
SSD workload completed **117,134 HTTP requests** with 100 authenticated accounts,
100 live connections, imports, concurrent edits/uploads and a real graphical
Office editor. Ten mixed minutes included 7,421 creates, 7,293 edits, 3,861
attachments, 2,420 Drive versions and 64 actual Office saves, with zero failed
measured mixed operations. Restart checks verified acknowledged snapshots and
file/history bytes; 100 intentionally interrupted transports reconciled exactly
once. See [the qualification report](../concurrency-qualification.md) for hashes,
deadlines, host/admission configuration, retained failures and final release checks.

The actual publisher-signed package passed RC.10-to-RC.11 activation, verified
final backups, paired rollback and interrupted-worker recovery. The updater UI
passed Chromium/Brave/Firefox/WebKit checks; an existing 10,623-record database
retained complete content hashes across migration and restart.

These results qualify the stated SSD profile, not every deployment. The shared
USB rotational-HDD mixed workload failed unchanged write deadlines and remains
unqualified. The original 9 MB, heavily styled workbook still takes about
80–83 seconds to open on the tested home PC, exceeding the 60-second target.
No workbook content/formatting was stripped and no large-Excel speed fix is claimed.

This is not 1,000-user capacity, 100 graphical Office editors, physical power-loss,
EC disk-failure or arbitrary custom-business-policy certification. Linux WebKit
without worker graphics offers an explicit original-download fallback rather
than graphical Office editing. Desktop alert tests do not certify physical
Windows notification banners. Benchmark before expanding workload/hardware scope.
