# MX 1.0.0-rc.4

[Documentation](../README.md) · [Updates](../updates.md) · [Changelog](../../CHANGELOG.md)

**Release date:** 2026-10-17 (Asia/Manila). **Status:** release candidate.

**Importer hotfix replacement:** 2026-10-18, at the maintainer's explicit request.
The version stays `1.0.0-rc.4`; no RC.5 is published. This replacement changes the
native executable, frontend and signed update package. Earlier RC.4 artifacts
and source commits remain archived for traceability; the publisher key is unchanged.
N1 compatibility remains `1.0.0-RC.1`, NOA v1 and unchanged storage encoding 4.

An earlier documentation-only refresh on the same date left runtime bytes
unchanged. **This subsequent importer replacement does not.** Equal-version
protection remains enabled: an already-installed older RC.4 will not reinstall
automatically or through the ordinary update UI. It needs a verified operator
replacement with a backup. The maintainer explicitly authorized that replacement
for the local test. Earlier RC versions can obtain this RC.4 through the normal
signed-update workflow.

## Spreadsheet imports

Import mapped record values without uploading files, even when the module's
normal form requires attachments. No required settings are disabled, and no
attachments are fabricated. Non-attachment requirements, types, permissions,
relationships and unique values remain checked.

Preview shows grouped problems with affected-row counts before any record is
saved. An all-invalid preview cannot start. If an older attempt saved no records,
open it in Import history, choose **Review mapping and revalidate**, confirm the
mapping, then **Validate and preview**. This replaces stale errors without
uploading again or saving records until Start. Successfully imported jobs cannot
be remapped. Ignored columns restore safely when reopening the mapping.

## Database contention hotfix

RC.4 moves application schema initialization and compatibility backfills to
startup, before accepting requests or starting background jobs. Runtime schema
guards become no-ops for that initialized database. Ordinary read handlers no
longer compete for SQLite's write lock merely to check tables or repeat legacy
updates, and record creation/editing no longer repeats a whole-table revision
repair. This is not a record-count cap or an increased lock timeout.

Audit-history reconciliation uses a new additive lookup index and indexed time
ranges. Imported-record audit entries are now committed in the same transaction
as their records and versions, rather than reconstructed by a later request.
Existing missing history is reconciled at startup, with stable event identifiers
preventing duplicate reconstruction after subsequent restarts.

Existing records, import progress, failed-row logs, versions, permissions,
credentials, branding and N1 objects remain in place. Do not reset or re-import
successful records. Startup still applies required compatibility migrations;
a migration failure prevents the server from accepting normal traffic.

## Install

For an earlier RC, in **Administration → Updates**, check for updates, download and verify RC.4,
then install it. The existing publisher key and independent worker take and
verify the final SQLite backup before switching the paired server/frontend.
The signed `.mxupdate` also supports offline upload through the same UI.
No SSH, database reset, N1 update or new trust key is required for a managed RC.

After reconnection reload the workspace, confirm `1.0.0-rc.4`, inspect import
history, open the imported module and verify normal reads and a record save.
Existing browser-local Office drafts stay on their original browser origin.

Qualification evidence is recorded in [TESTING.md](../../TESTING.md). This is
not a guarantee of unlimited throughput: SQLite still serializes real writes.
RC.1's remaining stable-release and physical-power-loss qualification limits
continue to apply.
